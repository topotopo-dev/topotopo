# TopoTopo v0.3

Release date: 2026-10-24. Published outputs and export targets that live in the graph, a reorganised viewer, and a
script time-limit fix. Graphs from v0.2 cook unchanged: the graph format is still version 1, and `outputs` and
`export` are optional. The node set is the same as in v0.2 (224 node types, 37 shelf assets, 34 example graphs).

## Published outputs

A graph can name the results it is meant to deliver, next to its default `output`:

```json
"outputs": { "rotor": { "node": "rotor_final", "label": "Rotor" } }
```

The viewer, MCP and the CLI list them; intermediate nodes stay in the outliner. Renaming or removing a node through
`edit` keeps the published references in step.

## Exports follow the graph

Where a result goes is stored in the graph: `"export"` on the graph is the default output's target, and
`outputs.<id>.export` a named output's. A target is a format (`"glb"` writes `exports/<graph or id>.glb`) or an object
with a format, an optional path and the export tool's options (`{"format": "obj", "path": "parts/rotor.obj",
"up_axis": "z"}`), always inside `exports/`.

- Viewer: each output card has one **Export** button. The first click asks for a format and a file and stores that
  target in the graph (`topotopo view` writes it back into the graph file); later clicks overwrite the same file.
  **Export all** writes every target. All of them cook and serialize before any file is written, and two targets
  that name the same file are refused. A texture card's menu downloads the texture as a PNG.
- MCP: `export {output: "rotor"}` writes one output's target, `export {all: true}` all of them; explicit paths still
  work. The `edit` op `export` sets a target.
- CLI: `topotopo graph.json --export-all` writes every target into `exports/` beside the graph.

## Viewer

- The left panel has three tabs: **Scene** (the outliner tree), **Outputs** (the default) and **Inputs**. Outputs
  shows all graphs' default and named results as cards with their textures; clicking one isolates it with its own
  camera, and **Scene** in the top bar restores the scene. Inputs lists the files in `inputs/` with **Add input** (or
  drop files anywhere on the page).
- Images open in a 2D viewer with pan and zoom, layers and channels (generated textures default to RGB; A shows
  packed alpha or AO) and mesh UVs. JPEG and WebP are viewable references only.
- The default navigation is the **TopoTopo** keymap: right-drag orbits around the surface under the cursor,
  middle-drag pans, the wheel zooms toward the cursor. F/A frame, 1–4 pick cameras, 5–7 change shading, O toggles
  orthographic and Space the quad view. The Maya, Houdini and Blender presets remain, including saved choices.
- The status line follows the workspace: an empty workspace shows the hint until the first graph arrives, and the
  hint no longer stays after it.

## Agents and MCP

- Every tool answer ends with a note when `inputs/` has files that are new or changed since the agent's last call, so
  the agent hears about what a person dropped in without asking.
- A render without `save_to` overwrites `exports/renders/<graph>-<node>.png` instead of adding a numbered file and a
  receipt per render (an agent renders after most edits, so they piled up).
- The `preview` tool's description names the current viewer (outliner, quad views, Controls).

## Fixes

- **Scripts**: when a script's time limit stopped it right after `lib.run` started an async node, the node's promise
  could reject later with nobody listening, which ended the process (the MCP server too). `lib.run` now awaits the
  node with no call in between, and the fuzz test reports a stray rejection against the case that caused it.
- The outputs scan can no longer throw from its timer when a file vanishes mid-scan (that ended the viewer's process,
  and the MCP server's when it hosts the viewer).
- The CLI keeps receipts only for files it writes inside `exports/`, instead of writing `exports/.outputs.json` beside
  every graph it rendered or exported.
- Zipped exports use entry names relative to the folder the files share, so none starts with `../`.

## Upgrading

```bash
npm install -g topotopo@0.3.0      # or: npx -y topotopo@latest mcp --workspace /absolute/path/to/workspace
```

MCP clients that start the server with `npx -y topotopo mcp` pick up v0.3 on their next start (npx may keep a cached
copy; `npx -y topotopo@latest` forces the new one).

Everything else, including the known limits, is as described in the [v0.2 release notes](v0.2-release-notes.md).
