# DNS for topotopo.dev (GitHub Pages)

The documentation site is built and deployed by `.github/workflows/pages.yml` (see its header). For it to answer at
https://topotopo.dev, the domain needs the records below. topotopo.dev is registered in the Cloudflare account and its
mail goes through Cloudflare Email Routing: **leave the mail records exactly as they are.**

## 1. Verify the domain for the GitHub organisation (recommended first)

GitHub → organisation `topotopo-dev` → Settings → Pages → Add a domain → `topotopo.dev`. GitHub shows a TXT record to
add; it looks like this (the value is generated by GitHub):

| type | name | content |
|---|---|---|
| TXT | `_github-pages-challenge-topotopo-dev` | *(value shown by GitHub)* |

Once GitHub reports the domain as verified, no other GitHub account can claim it for a Pages site. The TXT record must
stay in place.

## 2. Records for the site

In Cloudflare → topotopo.dev → DNS → Records. Set the proxy status of all of these to **DNS only** (grey cloud): a
proxied record hides GitHub's servers and blocks the HTTPS certificate GitHub requests for the domain. Remove any other
A, AAAA or CNAME record on `@` or `www` first (a parking page, for example).

Apex (`topotopo.dev`), GitHub Pages addresses:

| type | name | content | proxy |
|---|---|---|---|
| A | `@` | `185.199.108.153` | DNS only |
| A | `@` | `185.199.109.153` | DNS only |
| A | `@` | `185.199.110.153` | DNS only |
| A | `@` | `185.199.111.153` | DNS only |
| AAAA | `@` | `2606:50c0:8000::153` | DNS only |
| AAAA | `@` | `2606:50c0:8001::153` | DNS only |
| AAAA | `@` | `2606:50c0:8002::153` | DNS only |
| AAAA | `@` | `2606:50c0:8003::153` | DNS only |

`www` (GitHub redirects it to the apex):

| type | name | content | proxy |
|---|---|---|---|
| CNAME | `www` | `topotopo-dev.github.io` | DNS only |

Do not put a CNAME on the apex: it would collide with the MX records. If the zone has CAA records, one of them must
allow Let's Encrypt (`0 issue "letsencrypt.org"`); with no CAA records at all, nothing is needed.

## 3. Keep the mail records

These belong to Cloudflare Email Routing (hello@topotopo.dev → office@faxcorp.dev). Do not edit or delete them:

| type | name | content |
|---|---|---|
| MX | `@` | `route1.mx.cloudflare.net` (and `route2`, `route3`, with Cloudflare's priorities) |
| TXT | `@` | `v=spf1 include:_spf.mx.cloudflare.net ~all` (SPF) |
| TXT | `cf2024-1._domainkey` | the DKIM key Cloudflare created |

The A/AAAA records on `@` sit next to the MX and SPF records without conflict.

## 4. Repository settings

1. Make the repository public (or use a plan that allows Pages for private repositories).
2. Repository → Settings → Pages → Build and deployment → Source: **GitHub Actions**.
3. Run the **Pages** workflow (Actions → Pages → Run workflow), or push to `main`.
4. Settings → Pages → Custom domain: `topotopo.dev` → Save. GitHub checks the DNS records (minutes to an hour after
   the records are added).
5. When the certificate has been issued, tick **Enforce HTTPS**.

## 5. Check

```bash
dig +short topotopo.dev A          # the four 185.199.10x.153 addresses
dig +short topotopo.dev AAAA       # the four 2606:50c0:800x::153 addresses
dig +short www.topotopo.dev CNAME  # topotopo-dev.github.io.
dig +short topotopo.dev MX         # still the three route*.mx.cloudflare.net hosts
curl -sI https://topotopo.dev | head -1
```

On Windows: `nslookup -type=A topotopo.dev`, `nslookup -type=MX topotopo.dev`. Then send a test mail to
hello@topotopo.dev to confirm routing still works.
