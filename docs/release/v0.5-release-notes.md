# TopoTopo v0.5

Release date: 2026-11-04. TopoTopo v0.5 brings versioned procedural packages, game workspaces, a web app that follows your folders and a Godot
importer. It also expands PBR texture authoring and improves UV, rendering and mesh operations.

## Packages and workspaces

A package holds graphs, inputs, published outputs and frozen versions in one folder, identified by an `<id>.topo`
file. Outputs can be meshes, instances, points, curves, terrain, textures, materials, volumes or scenes. Packages
use other packages by name; copied versions keep an asset reproducible, and updates show a before/after comparison.
TopoTopo's built-in architecture, nature, props and street assets use the same package system.

A workspace groups the packages of a game or 3D project. It lists shared libraries once and keeps one shared copy
of the package versions it uses. Packages are discovered through the folder tree, and exports stay beside the package.
Material-only outputs can be published and reused on meshes, with their texture maps.

`topotopo check` cooks packages and reports what needs fixing. `--locked` refuses to add a missing package version
during a graph cook, which is useful for a build machine.

## The web app follows your folders

`topotopo web` opens your registered workspaces and libraries. Folders have their own pages; package pages show
previews, graphs, controls, published outputs and versions. Notes can include images and relative links, and media
files can be viewed alongside the assets they describe. The viewer and agent use the same package sources.

## Godot integration

`topotopo godot setup <project folder>` installs the GDScript addon. A package inside the Godot project imports
through its `.topo` file; each published output becomes a regular GLB that Godot imports and you can place in scenes.
Live Cook keeps it current while preserving import settings. Failed cooks keep the last good output.

The plugin supports instancing, materials, LOD pieces and sockets. TopoTopo's working files are kept out of Godot's
resource importer and exports. Committing cooked outputs lets teammates and build machines use the game without
installing TopoTopo.

## PBR texture authoring and asset fixes

Texture nodes now include signed-distance shapes and operations, mask bevels and distances, flood fill, slope and
directional blur, seamless tiling, grunge, histogram controls, normal-map tools, curvature and AO. Distance-based
controls use metres, so a material's features can keep their physical size across resolutions.

UV packing and per-piece unwrapping are more robust, and decimation/LOD has a UV-preserving path. Renders fit the
asset's bounds and offer transparent backgrounds, diagonal cameras, reference overlays and socket previews.
Inspection reports identify the affected parts and positions more clearly.

## Guide authoring

Move guides directly in the viewer, drag a curve's control points and add or remove them with a double-click.
Visible guide tools switch to the scene view, and guide changes recook the scene. Drags use reference surfaces or
the point's editing plane. The guided-town example turns roads, footprints and placement guides into a scene.

## Upgrading from v0.4

This release changes the asset workflow. Back up authored sources and published versions before converting an old
library or workspace.

- Asset `project.json` manifests become `<id>.topo` package manifests. A game or 3D project is the workspace;
  shared library selection belongs in its `topotopo-workspace.json`.
- `topotopo gallery` becomes `topotopo web`, and the MCP `library` tool becomes `workspace`. Update client prompts
  and scripts that name the old commands or tool.
- Exports use paths inside the package's `exports/` folder. Old `engine:` export targets are rejected.
- UV parameters and defaults changed. Recheck `uv_unwrap` and `uv_layout` against `--help-node` before recooking
  existing graphs; review their UVs and downstream bakes.
- Old shelf assets are published outputs of TopoTopo's built-in packages. Use their full package/output names.

The existing Unreal PCG and Landscape integration remains available. The new `.topo` importer in this release is
for Godot; the corresponding Unreal importer is planned separately.
