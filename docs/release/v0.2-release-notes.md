# TopoTopo v0.2

Release date: [verify: tag date]. First public release.

TopoTopo is a procedural geometry engine: Houdini-style node graphs, headless, deterministic, exports to Unreal,
Blender and Houdini. You write a graph as JSON; the engine cooks it into geometry on Node.js, with no GPU and no
editor, and every cook is reproducible from the graph and its seeds.

Draft notes for the v0.2 tag. Numbers are taken from the repository at commit f6de66b (2026-10-13); re-check them
against `docs/nodes.md`, `test/golden/` and `docs/WORKLOG.md` when tagging. Items marked [verify] depend on the rename
commit (WORKLOG R-4) or could not be confirmed from the repository.

## What is in v0.2

217 node types in 18 categories, 37 shelf assets, 30 example graphs. Every node documents its parameters and carries
an example that the tests cook. The full reference is [docs/nodes.md](../nodes.md).

### Modelling
- Generators (box, sphere, tube, torus, platonic, grid, terrain, L-systems, text with the bundled DejaVu Sans font),
  transforms and deformers (noise, twist, bend, taper, soft transform with falloff, lattice, path and point deform,
  rest positions).
- Polygon editing on a cached half-edge structure: `poly_bevel` (edge and point, chamfer and round), `poly_extrude`,
  `knife`, `polysplit`, `polybridge`, `polyfill` (quad fill), `edge_divide`, `dissolve`, `edge_collapse`, crease-aware
  `subdivide`, hard-edge `normal`.
- Point, vertex, primitive and edge groups with Houdini-style patterns; float, int and string attributes, including
  array attributes.
- Solids through manifold-3d: robust booleans, hull, Minkowski, clip, slice, Voronoi fracture.

### Curves
- Bezier and NURBS primitives evaluated exactly wherever they are used, sweeps, revolve, loft, 2D offsets and booleans,
  `fillet_curve`, `offset_curve_3d`, `spline_fit`, `project_curve` (roads on terrain), `curve_attribs` (curveu,
  frames, ramps).
- `straight_skeleton` (Rust/WASM): pitched roofs and polygon offsets for any footprint, holes included.

### Instancing and PCG
- Packed primitives: `copy_to_points {pack: true}` keeps a million copies as a million points plus shared meshes, with
  variants chosen by attribute or weights; `pack`, `unpack`, automatic unpacking with a warning where needed.
- `scatter` by count or density per m², density attribute and mask, blue noise, relaxation, exact minimum distance.
- PCG nodes: `mask` (slope, height, curvature, occlusion, distance, direction, noise), `attribute_from_map`, `orient`,
  `points_along_curve`, `cluster`, `prune`.

### Terrain
- 24 heightfield nodes: noise, masks, blur, terrace, cutout, roads (`heightfield_path`), projection of meshes and
  curves, scatter, conversion to mesh and SDF.
- `heightfield_erode` with three methods: droplet (TypeScript by default, or the WASM kernel), virtual-pipe shallow
  water, and pipes with stream-power incision, plus a thermal pass. `heightfield_flow` writes D8 or D-infinity
  drainage.
- Export as Unreal Landscape heightmaps (16-bit PNG or RAW `.r16` with a JSON sidecar), 8-bit weight layers, or one
  `unreal_landscape` bundle with a manifest of the exact Landscape import settings.

### Volumes, remeshing and UVs
- Implicit SDFs (shapes, expressions, smooth combine) and sampled SDF grids (Rust/WASM) with CSG, offset, blur,
  dilate, erode, resample, and meshing by sharp dual contouring or marching cubes (`voxel_remesh`).
- `remesh_isotropic`, field-aligned quad-dominant `remesh_quad` (Rust/WASM), attribute-preserving `decimate`
  (meshoptimizer), `mesh_repair`, `lod`.
- `uv_unwrap` (xatlas), `uv_flatten` (LSCM), `uv_layout`, `uv_autoseam`, and a UV view in the renderer.

### Textures and bakes
- 37 texture nodes: generators (noise, patterns, cells, shapes, gradients, splatter, scratches, text), filters
  (blend, levels, curves, blur, warp, normal from height, AO from height, channel packing, tile sampler) and bakes in
  uv space (AO, curvature, thickness, position, normals, height from a high-res mesh, island ids, masks, vertex
  colour).
- Images travel with the geometry; materials reference them as `image:<name>`; glTF embeds them, USD writes them next
  to the file, and the `textures` export writes PNGs.

### Engine
- Lazy cooking from the output node, a content-signature cache (an edit re-cooks only what is downstream), per-node
  errors with did-you-mean hints, Houdini aliases (`copytopoints`, `attribwrangle`, `polyextrude` …).
- Expressions in any parameter (`"=count * 2"`) that can read other nodes: `npoints`, `bbox`, `centroid`, `detail`,
  `point`, `prim`, `ch`.
- Time: every cook happens at a frame; only time-dependent nodes re-cook; a `solver` node with cached frame states.
- `foreach`, `switch`, `graph_ref`, saved assets; graph versioning with migrations and node deprecation.
- A worker pool for heavy per-element work and concurrent branches, with output identical bit for bit to the serial
  path.
- Code nodes: `wrangle` (per element, VEX-style `@P` syntax) and `script` (whole geometry), run in a separate realm
  with a timeout (see Security below).

### Shelf
37 graph assets used like nodes: walls, windows, doors, a whole `house` built from other assets, gable, hip and
straight-skeleton roofs, stairs, railings, fences, bricks, tiles, props, trees, rocks and PCG helpers. A workspace
asset with the same name overrides a shelf asset.

### Rendering and preview
- A software renderer (no GPU): quad views, turntables, UV view, texture view, colour by attribute, group highlights,
  flipped normals in blue, section and clip planes with caps, wireframe overlays (all, hard, boundary, groups), normal
  and orientation glyphs, labels, matcap and AO shading.
- A live three.js preview that updates when a graph changes.

### Agent and MCP support
An MCP server with 12 tools: `catalog`, `help`, `build`, `edit`, `inspect`, `render`, `export`, `graphs`, `assets`,
`explain`, `diff`, `preview`. An agent can build a whole graph in one call, edit it incrementally, look at a render,
and verify its work with `assert` nodes, `explain` (shape descriptors in words) and `diff` (Hausdorff distance between
versions).

## Interop and verification

Export formats: GLB/glTF through glTF Transform (materials with embedded textures, `EXT_mesh_gpu_instancing` with
per-instance attributes, optional meshopt compression and quantization), USDA (PointInstancer, UsdPreviewSurface),
Houdini `.geo` (every attribute and group, packed prims as PackedGeometry), CSV and `points.json` instance streams with
Unreal PCG columns, OBJ, PLY, STL and lossless JSON, with Y- or Z-up and scale. The `file` node reads glTF (including
meshopt and external buffers), `.geo`, uncompressed `.bgeo`, CSV, `points.json`, OBJ, PLY, STL and JSON.

`npm run export:demo` writes the demo scene (`examples/unreal_demo.json`: a 126 × 126 m eroded terrain, a road, 292
trees and 244 rocks as 536 packed instances) as a Landscape bundle, GLB, USDA, `.geo` and an instance stream. That
file set was checked in three applications on 2026-10-13:

- **Unreal Engine 5.8.** The Landscape imported with the manifest values (section size 63, 2 × 2 sections, 2 × 2
  components, scale (50, 50, 4.603792), location (0, 0, 1169.3223)); line traces show the terrain ending at ±6300 cm,
  the low corner at the exported minimum height, and the tree bases on the surface (median gap 0.16 cm). The 536 CSV
  rows were spawned as actors; applied with Unreal's rotator convention they put all 39,350 transformed vertices
  within 0.1 cm of the reference geometry, and row 0 reads back from the editor equal to the CSV. GLBs import through
  Interchange with their materials; the axis mapping is X = x, Y = z, Z = y.
- **Blender 5.2.** `scene.glb` imports as 536 instances sharing 5 mesh datablocks with 7 materials; `scene.usda` as 7
  meshes plus the PointInstancer.
- **Houdini 22.0.466.** `scene.geo` loads with 0 errors: 63,645 polygons and 536 PackedGeometry primitives over 5
  embedded sources, every point, primitive, vertex and detail attribute present.

Testing: `npm test` runs 32 test programs: smoke (every node type on its fixture), 282 golden fingerprints (every node
fixture, example graph and shelf asset), property tests on 150 random node chains, a wrangle fuzz, docs staleness,
every node's example, a NOTICE check, export/import round trips for every format, interop checks (every GLB through
the Khronos glTF validator), the MCP server end to end over stdio, and suites per feature. The Rust kernels have 76
tests of their own.

## Known limits

From the work-item notes in `docs/WORKLOG.md` and the measurements in `kernels/BENCH.md` (Intel i7-10700K):

Performance
- `remesh_quad`: 100k triangles take 8.4 s (sphere) and 4.4 s (grid) in Node, against a 3 s target. The large sphere
  has 2.7% irregular vertices, 9.7% with UV seams; quads-only mode overshoots the face target and pinches tube caps.
- `heightfield_erode`: the pipe model takes 21.8 s in Node (12.8 s native) for 1024² × 200 steps, against a 4 s
  target; the WASM droplet kernel runs at the speed of the TypeScript one (about 2 s for 512² × 100).
- Sampled SDF grids: a 256³ band with dual contouring takes 1.8 s (target 1.5 s); filled mode 12.5 s.
- AO bake 2048² × 16 rays about 6 s; `uv_unwrap` about 2.7 s per 20k triangles (xatlas-bound); occlusion 50k × 32 rays
  about 2 s; relaxed scatter about 2.5 s per 100k points.

Quality
- Dual contouring leaves fine serration along sharp edges; there is no adaptive octree; winding numbers for open
  meshes are approximate.
- `straight_skeleton` accepts at most 4096 vertices; some near-degenerate events return an error instead of a result.
- Bit identity across platforms is tested by replay and one native/WASM comparison, not by a full platform matrix.
- `poly_bevel` skips boundary edges, clamps with one global factor, and relaxes irregular round corners rather than
  making them spherical. `lattice` cages are axis-aligned; `path_deform` follows polylines only.
- `uv_layout` packs bounding rectangles; `uv_autoseam` is rough.
- meshoptimizer can pinch thin parts at very low decimation ratios.
- Heightfields are axis-aligned. Unreal's Landscape is piecewise linear along one cell diagonal while TopoTopo samples
  bilinearly, so scattered points can sit a few centimetres off on steep cells [verify: whether the
  Unreal-triangulation sampling option (WORKLOG R-8) is merged before the tag].
- Splines are written to `.geo` and USD as polylines; `fillet_curve`, `offset_curve_3d` and `project_curve` output
  polylines.
- Textures: colour is stored display-referred; no MikkTSpace tangents; bakes cover the 0..1 uv square only; no node
  reads a PNG into an image yet.
- `roof_hip` handles rectangles only (`roof_skeleton` handles any footprint).
- The self-intersection check in `assert` misses coplanar overlaps; `assert` expressions cannot read graph vars.
- `script` syntax errors have no line hint. Examples that cook with warnings: `dissolve`, `spline_fit`,
  `mesh_repair`, `bake_curvature`.
- Time: the live viewer cooks frame 1, MCP `export` writes a single frame, and `sdf_expr` and parametric code cannot
  read time.
- No GUI node editor yet; the live viewer shows results only.

Unreal
- The Landscape import is still done by hand in Landscape mode, with the values from `landscape.json`. Importing the
  weight-layer PNGs into Landscape paint layers has not been checked in the editor.
- Loading `instances.csv` into a PCG graph with *Load Data Table* needs a user-defined row struct first (Mesh Name,
  Position Vector, Rotation Rotator, Scale Vector) and the `--pcg-struct` CSV variant. A UE plugin that reads the
  stream directly is planned.
- Export OBJ with `up_axis: z` for Unreal; Unreal keeps a Y-up OBJ lying on its side.

Security
- A graph is code. `wrangle`, `script` and `sdf_expr` run JavaScript in a Node `vm` realm with a timeout, which stops
  runaway loops but is not a security boundary, and `"=expr"` parameters are evaluated as JavaScript in the engine's
  own realm (`src/graph/params.ts`). Do not cook graphs, shelf assets or workspace assets from sources you do not
  trust, and do not expose the MCP server to untrusted clients.

## Install and quick start

Requires Node.js 22.18 or later.

```bash
npx topotopo --catalog                     # node types by category
npx topotopo --help-node scatter           # one node's params, defaults and example
npx topotopo graph.json --render out.png --export out.glb
npx topotopo level.json --node landscape --format unreal_landscape --export out/level   # Landscape bundle
```

Or install it globally and use the short alias:

```bash
npm install -g topotopo
topo graph.json --render out.png
```

[verify: the published package must run from `node_modules`. Node refuses to strip types from `.ts` files under
`node_modules` (`ERR_UNSUPPORTED_NODE_MODULES_TYPE_STRIPPING`, confirmed with Node 24.14 on 2026-10-13), and today's
package ships TypeScript sources with no `bin` entry. The rename commit or the release step has to add the `bin`
entries and publish JavaScript (for example compiled at pack time) before these commands work.]

From a clone, which works today:

```bash
git clone https://github.com/topotopo-dev/topotopo
cd topotopo
npm install
npm test
node src/cli.ts examples/house_city.json --render out/house_city.png --export out/house_city.glb
npm run export:demo        # the Unreal/Blender/Houdini file set in out/unreal_demo/
npm run preview            # the examples in the live viewer
```

A minimal graph:

```json
{
  "vars": { "count": 200 },
  "nodes": {
    "ground": { "type": "terrain", "params": { "size": [30, 30], "height": 3 } },
    "pts":    { "type": "scatter", "in": ["ground"], "params": { "count": "=count", "seed": 1 } },
    "rock":   { "type": "sphere", "params": { "type": "ico", "level": 2, "radius": 0.3 } },
    "rough":  { "type": "noise_displace", "in": ["rock"], "params": { "amplitude": 0.08, "frequency": 4 } },
    "rocks":  { "type": "copy_to_points", "in": ["rough", "pts"] },
    "out":    { "type": "merge", "in": ["ground", "rocks"] }
  }
}
```

### MCP server

For Claude Desktop and other MCP clients:

```json
{
  "mcpServers": {
    "topotopo": {
      "command": "npx",
      "args": ["-y", "topotopo", "mcp", "--workspace", "/absolute/path/to/workspace"]
    }
  }
}
```

For Claude Code:

```bash
claude mcp add topotopo -- npx -y topotopo mcp --workspace /absolute/path/to/workspace
```

[verify: how the package exposes the MCP server (a `mcp` subcommand, as written here, or a separate bin) is decided in
the rename commit.] From a clone, point the client at the server file instead:
`"command": "node", "args": ["/path/to/topotopo/src/mcp/server.ts", "--workspace", "/path/to/workspace"]`. The
repository's `.mcp.json` registers it for Claude Code sessions opened in the folder. Options: `--viewer` starts the
live preview at once; the workspace, viewer port, script timeout and worker count can also be set by environment
variables (see the rename table above). The server exits when the client closes its stdin.

## Licence and contributing

TopoTopo is licensed under Apache-2.0 (see LICENSE), copyright faxcorp. NOTICE lists every third-party component with
its full licence text; `npm test` fails if it is out of date. There is no paid edition and no feature held back.

The project has one maintainer, and reviews can take weeks. Read CONTRIBUTING.md before opening a pull request: open
an issue before large changes, every node needs tests, docs and an example, commits are signed off under the DCO
(`git commit -s`), and bug reports must include the graph JSON that reproduces the bug. The project follows the
Contributor Covenant 2.1 (CODE_OF_CONDUCT.md). Contact: hello@topotopo.dev.

How it was built: most of the code was written by AI coding agents (Anthropic Claude models for the engine, OpenAI
Codex sessions for the Rust kernels) working on scoped items under the maintainer's direction. Every merge passed the
type checker, the full test suite and a review of the rendered examples.
